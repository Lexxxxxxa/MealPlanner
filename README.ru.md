# MealPlanner

[English](README.md) | [Deutsch](README.de.md) | [Русский](README.ru.md)

Telegram-бот для пары (или семьи): общий список блюд с подсчётом калорий и БЖУ, учёт запасов,
подсказки «что приготовить из того, что есть» и меню на день. Для курсовой работы в проекте есть экспериментальная часть:
сравнение стратегий рекомендаций, подбор замен ингредиентов и планирование меню из ограниченных запасов.

> Интерфейс бота на украинском языке. Ниже названия кнопок приведены так, как они выглядят в боте, с переводом.

## Структура

| Проект | Назначение |
|---|---|
| `src/MealPlanner.Core` | Модели, разбор текста блюд, алгоритмы меню (жадный, симплекс), рекомендации, замена ингредиентов, каталог продуктов `Data/foods.csv` |
| `src/MealPlanner.App` | EF Core + SQLite (домохозяйства, блюда), `BotUi` (кнопочный интерфейс) и `CommandHandler` (текстовые команды) — без зависимости от Telegram |
| `src/MealPlanner.BotHost` | Консольный хост Telegram-бота (long polling) |
| `src/MealPlanner.Benchmark` | Эксперименты 0–3, результаты в `results/*.csv` |
| `tests/MealPlanner.Tests` | Модульные тесты xUnit (парсер, алгоритмы, команды бота на SQLite in-memory) |

## Запуск

Нужен .NET 8 SDK.

```bash
dotnet build
dotnet test
```

### Бот

1. Создайте бота в Telegram через `@BotFather` и скопируйте токен.
2. Узнайте свой Telegram-ID и ID партнёра (например, через `@userinfobot`).
3. Запустите (Windows PowerShell):

```powershell
$env:TELEGRAM_BOT_TOKEN = "123456:ABC..."
$env:ALLOWED_USER_IDS = "11111111,22222222"
dotnet run --project src/MealPlanner.BotHost
```

Не храните токен в репозитории. `ALLOWED_USER_IDS` ограничивает доступ вашей парой.
В чате: `/start`, затем партнёр отправляет `/join КОД`.

Весь интерфейс — кнопки (меню внизу экрана):

- **🍳 Що приготувати** (Что приготовить) — отметьте имеющиеся продукты (категории → продукты) или напишите списком; бот подберёт блюда из вашей базы и идеи из встроенных.
- **📖 Мої блюда** (Мои блюда) — список с калориями, состав, удаление. В карточке блюда:
  - **✏️ Змінити** (Изменить) — изменить, добавить или убрать продукты, граммы (кнопки −50/−10/+10/+50 или число), количество порций; «Зберегти» (Сохранить) обновляет рецепт.
  - **👩‍🍳 Готую** (Готовлю) — то же, но с фактическими граммами: бот показывает калории и БЖУ «по факту» в сравнении с рецептом (разница на порцию), можно записать порцию в дневник или обновить рецепт.
  - **🍽 З'їв(ла)** (Съел(а)) — записать в дневник ½, 1, 1½, 2 или 3 порции.
- **📝 Рецепт.** У каждого блюда есть время приготовления и шаги («Як готувати», как готовить). Кнопки «📝 Рецепт» и «🗑 Прибрати рецепт» (Убрать рецепт) в карточке блюда позволяют добавить или изменить шаги; в режиме «Готую» шаги показываются рядом с граммами. Шаги для блюд встроенной базы сгенерированы по шаблонам в зависимости от типа блюда — это черновики, их стоит просмотреть и исправить.
- **⏱ Время и сложность.** При добавлении блюда после порций выбираются время приготовления (10–90 мин) и сложность (легко / средне / сложно); их можно изменить в «Змінити». В «Що приготувати» кнопки фильтров «⚡ До 20 мин» и «🔧 Складність» (Сложность: любая → несложные → только лёгкие) отсекают лишние варианты.
- **💡 Що з'їсти до норми** (Что съесть до нормы, на экране дня): бот берёт остаток калорий и БЖУ на сегодня и подбирает из ваших блюд и встроенных идей порции (½, 1, 1½, 2), лучше всего закрывающие остаток. Оценка = |Δккал| / остаток ккал + Σ по Б, Ж, У (0,5 · превышение + 0,25 · недобор) / max(остаток, 10); варианты калорийностью выше 110 % остатка отбрасываются. Из карточки можно сразу записать порцию в дневник.
- **📅 Щоденник** (Дневник) — сумма калорий и БЖУ за день относительно личной цели (по умолчанию 2000 ккал), прогресс-бар, запись продукта в граммах, удаление записи, просмотр предыдущих дней, кнопка «🎯 Моя ціль» (Моя цель). Дневник у каждого участника свой; значения КБЖУ в записях сохраняются снимком, поэтому изменение рецепта не переписывает историю.
- **🛒 Режим «с докупкой»** в «Що приготувати»: если из выбранных продуктов блюдо не собрать, бот показывает блюда, где они используются, и что нужно докупить; переключатель «Лише з моїх продуктів» (Только из моих продуктов) возвращает строгий подбор.
- **📚 База блюд** — встроенная база примерно из 390 готовых блюд в 15 категориях (завтраки, супы, салаты, мясные, из птицы, рыбные, овощные, каши, паста, бобовые, выпечка, десерты, закуски, напитки, быстрые). Постраничный просмотр по категориям, поиск по названию или продукту («форель», «творог яйца»), фильтры «до 20 мин» и по сложности, кнопка «🎲 Випадкове» (Случайное), сохранение в «Мої блюда» одним нажатием и запись порции в дневник.
- **🔎 Поиск продуктов** есть везде, где выбираются продукты (идеи, добавление и изменение блюда, дневник); списки продуктов разбиты на страницы по 12. В каталоге 392 продукта в 25 категориях (начальные 59 + расширенный набор).
- **➕ Додати блюдо** (Добавить блюдо) — название → продукты кнопками → граммы кнопками (или число / «3 шт») → порции → время → сложность → способ приготовления (текстом, по шагу на строку, или «Пропустити» — пропустить).
- **👫 Пара** — код домохозяйства для общей базы блюд.

**🎯 Моя ціль** (Моя цель) — мастер из 6 шагов (пол → возраст → рост → вес → активность → цель). На каждом шаге виден ориентир дневной нормы, который уточняется по мере ввода данных; на кнопках активности и цели показана соответствующая норма. Расчёт: ИМТ (с категорией ВОЗ), основной обмен по Миффлину — Сан-Жеору, множитель активности (1,2–1,725) и поправка по цели: похудеть −15 % (не ниже 1200/1500 ккал), удерживать вес 0 %, набрать +10 %. Доли БЖУ зависят от цели (похудеть 25/30/45, удерживать 20/30/50, набрать 20/25/55). Норму можно задать и вручную. Результаты ориентировочные и не заменяют консультацию врача.

Существующая БД при запуске автоматически дополняется таблицами дневника (`DiaryEntries`, `MemberTargets`).

Запасы «в холодильнике» не сохраняются: продукты указываются только в момент запроса идеи.
Текстовые команды (`/dish`, `/have`, `/cook`, `/menu` …) оставлены как скрытый запасной режим.

### Архитектура приложения

- `Core` — предметная логика без зависимостей от Telegram и БД (модели, рекомендательные алгоритмы, `PortionFit`, `EnergyCalculator`, `InstructionText`); стратегии `IDishRecommender`, `IMenuPlanner`.
- `App/Services` — сервисы и репозитории за интерфейсами (`IHouseholdService`, `IFoodRepository`, `IDishRepository`, `IPantryService`, `IDiaryService`); собирает их `AppServices.Create`. Инициализация БД — `DatabaseInitializer`.
- `App/Bot/Features` — по одному классу на раздел интерфейса (`IBotFeature`: префиксы callback и шаги сессии); `BotUi` только маршрутизирует, новая функция добавляется без изменения существующих. Общие вспомогательные функции — `UiKit`. Текстовые команды — реестр в `CommandHandler`.

### Запуск экспериментов

```bash
dotnet run -c Release --project src/MealPlanner.Benchmark -- all        # или menu | recommend | substitute | pantry
```

## Эксперименты

0. **Меню из полного каталога** — жадный алгоритм против LP (симплекс) на 59–1000 продуктах.
1. **Рекомендации** — Random, BinaryCoverage, WeightedCoverage и Smart (IDF-вес, штраф за докупку, согласование ккал) на синтетических домохозяйствах; Precision@5, Hit@1, отклонение калорийности.
2. **Замена ингредиентов** — Random, Macro, CategoryMacro, Oracle; погрешность калорийности и БЖУ блюда.
3. **Меню из запасов** — доля допустимых меню и стоимость в зависимости от количества продуктов в запасах.

## Математическая постановка меню («задача о диете»)

```
min  Σ pᵢ·xᵢ                              (стоимость)
при  minₖ ≤ Σ aᵢₖ·xᵢ ≤ maxₖ,  k = ккал, белки, жиры, углеводы
     0 ≤ xᵢ ≤ min(Mᵢ, запасᵢ)/100
```

## Данные каталогов

`foods.csv` — базовый набор из 59 продуктов (на нём выполняются эксперименты); `foods_extra.csv` — ещё 333 продукта; `dishes.txt` — около 390 блюд в формате `категория|название|мин|сложность|порций|продукт:граммы;…`. Значения КБЖУ на 100 г и цены ориентировочные, сведены из стандартных справочных таблиц химического состава пищевых продуктов; перед использованием в научной части их стоит сверить с официальными источниками (USDA FoodData Central, таблицы Скурихина). При запуске бота продукты, которых ещё нет в базе, добавляются автоматически, поэтому обновление не требует пересоздания БД. Тест `DishCatalog_ResolvesEveryProduct` гарантирует, что каждый ингредиент каждого блюда есть в каталоге.

## Замечания о данных

Пищевая ценность и цены в `foods.csv` — ориентировочные справочные значения для обучения, не официальные данные.
Эксперименты 0–3 выполняются на синтетических данных (блюда и «холодильники» генерируются детерминированно),
поэтому выводы относятся к модели, а не к реальному поведению пользователей.
