# MealPlanner

Telegram-бот для пари (або сім'ї): спільний список блюд із підрахунком калорій і БЖВ, облік запасів,
підказки «що приготувати з того, що є» та меню на день. Для курсової роботи в проєкті є експериментальна частина:
порівняння стратегій рекомендацій, підбір замін інгредієнтів і планування меню з обмежених запасів.

## Структура

| Проєкт | Призначення |
|---|---|
| `src/MealPlanner.Core` | Моделі, розбір тексту блюд, алгоритми меню (жадібний, симплекс), рекомендації, підстановка інгредієнтів, каталог продуктів `Data/foods.csv` |
| `src/MealPlanner.App` | EF Core + SQLite (домогосподарства, блюда), `BotUi` (кнопковий інтерфейс) і `CommandHandler` (текстові команди) — без залежності від Telegram |
| `src/MealPlanner.BotHost` | Консольний хост Telegram-бота (long polling) |
| `src/MealPlanner.Benchmark` | Експерименти 0–3, результати у `results/*.csv` |
| `tests/MealPlanner.Tests` | Модульні тести xUnit (парсер, алгоритми, команди бота на SQLite in-memory) |

## Запуск

Потрібен .NET 8 SDK.

```bash
dotnet build
dotnet test
```

### Бот

1. Створіть бота в Telegram через `@BotFather`, скопіюйте токен.
2. Дізнайтеся свій і партнера Telegram-ID (наприклад, через `@userinfobot`).
3. Запустіть (Windows PowerShell):

```powershell
$env:TELEGRAM_BOT_TOKEN = "123456:ABC..."
$env:ALLOWED_USER_IDS = "11111111,22222222"
dotnet run --project src/MealPlanner.BotHost
```

Токен не зберігайте в репозиторії. `ALLOWED_USER_IDS` обмежує доступ вашою парою.
У чаті: `/start` → партнер надсилає `/join КОД`.

Весь інтерфейс — кнопки (меню внизу екрана):

- **🍳 Що приготувати** — відзначте продукти, які є зараз (категорії → продукти) або напишіть списком; бот підбере блюда з вашої бази та ідеї зі вбудованих.
- **📖 Мої блюда** — список із калоріями, склад, видалення. У картці блюда:
  - **✏️ Змінити** — змінити/додати/прибрати продукти, грами (кнопки −50/−10/+10/+50 або число), кількість порцій; «Зберегти» оновлює рецепт.
  - **👩‍🍳 Готую** — те саме, але з фактичними грамами: бот показує калорії/БЖВ «за фактом» проти рецепту (різниця на порцію), можна записати порцію в щоденник або оновити рецепт.
  - **🍽 З'їв(ла)** — записати ½, 1, 1½, 2, 3 порції в щоденник.
- **⏱ Час і складність.** При додаванні блюда після порцій вибираються час приготування (10–90 хв) і складність (легко / середньо / складно); їх можна змінити в «Змінити». У «Що приготувати» кнопки фільтрів «⚡ До 20 мин» і «🔧 Складність» (будь-яка → не складні → тільки легкі) відсікають зайві варіанти.
- **💡 Що з'їсти до норми** (на екрані дня): бот бере залишок калорій і БЖВ на сьогодні та підбирає з ваших блюд і вбудованих ідей порції (½, 1, 1½, 2), що найкраще закривають залишок. Оцінка = |Δккал| / залишок ккал + Σ по Б, Ж, У (0,5 · перевищення + 0,25 · недобір) / max(залишок, 10); варіанти з калорійністю понад 110 % залишку відкидаються. З картки можна одразу записати порцію в щоденник.
- **📅 Щоденник** — сума калорій і БЖВ за день проти особистої цілі (за замовчуванням 2000 ккал), прогрес-бар, запис продукту в грамах, видалення запису, перегляд попередніх днів, кнопка «🎯 Моя ціль». Щоденник особистий для кожного учасника; значення КБЖВ у записах зберігаються знімком, тому зміна рецепта не переписує історію.
- **🛒 Режим «з докупівлею»** у «Що приготувати»: якщо з обраних продуктів блюдо не зібрати, бот сам показує блюда, де вони використовуються, і що треба докупити; перемикач «Лише з моїх продуктів» повертає суворий підбір.
- **📚 База блюд** — вбудована база із ≈ 390 готових блюд у 15 категоріях (сніданки, супи, салати, м'ясні, з птиці, рибні, овочеві, каші, паста, бобові, випічка, десерти, закуски, напої, швидкі). Перегляд за категоріями з посторінковою навігацією, пошук за назвою або продуктом («форель», «творог яйца»), фільтри «до 20 хв» і за складністю, кнопка «🎲 Випадкове», збереження в «Мої блюда» одним натисканням і запис порції в щоденник.
- **🔎 Пошук продуктів** є всюди, де обираються продукти (ідеї, додавання/зміна блюда, щоденник); списки продуктів розбито на сторінки по 12. Каталог містить 392 продукти у 25 категоріях (початкові 59 + розширений набір).
- **➕ Додати блюдо** — назва → продукти кнопками → грами кнопками (або число / «3 шт») → порції.
- **👫 Пара** — код домогосподарства для спільної бази блюд.

**🎯 Моя ціль** — майстер із 6 кроків (стать → вік → зріст → вага → активність → мета). На кожному кроці видно орієнтир норми на день, який уточнюється по мірі введення даних; у кнопках активності та мети показано відповідну норму. Розрахунок: ІМТ (з категорією ВООЗ), основний обмін за Міффліном–Сан-Жеором, множник активності (1,2–1,725) і поправка за метою: схуднути −15 % (не нижче 1200/1500 ккал), тримати вага 0 %, набрати +10 %. Частки БЖВ залежать від мети (схуднути 25/30/45, тримати 20/30/50, набрати 20/25/55). Норму можна й задати вручну. Результати орієнтовні й не замінюють консультацію лікаря.

Існуюча БД автоматично доповнюється таблицями щоденника (`DiaryEntries`, `MemberTargets`) при старті.

Запаси «в холодильнику» не зберігаються: продукти вказуються лише в момент запиту ідеї.
Текстові команди (`/dish`, `/have`, `/cook`, `/menu` …) залишено як прихований запасний режим.

### Експерименти

```bash
dotnet run -c Release --project src/MealPlanner.Benchmark -- all        # або menu | recommend | substitute | pantry
```

## Експерименти

0. **Меню з повного каталогу** — жадібний алгоритм проти LP (симплекс) на 59–1000 продуктів.
1. **Рекомендації** — Random, BinaryCoverage, WeightedCoverage і Smart (IDF-вага, штраф за докупівлю, узгодження ккал) на синтетичних домогосподарствах; Precision@5, Hit@1, відхилення калорійності.
2. **Підстановка інгредієнтів** — Random, Macro, CategoryMacro, Oracle; похибка калорійності й БЖВ блюда.
3. **Меню з запасів** — частка допустимих меню та вартість залежно від кількості продуктів у запасах.

## Математична постановка меню («задача про дієту»)

```
min  Σ pᵢ·xᵢ                              (вартість)
при  minₖ ≤ Σ aᵢₖ·xᵢ ≤ maxₖ,  k = ккал, білки, жири, вуглеводи
     0 ≤ xᵢ ≤ min(Mᵢ, запасᵢ)/100
```

## Дані каталогів

`foods.csv` — базовий набір із 59 продуктів (на ньому виконуються експерименти); `foods_extra.csv` — ще 333 продукти; `dishes.txt` — ≈ 390 блюд у форматі `категорія|назва|хв|складність|порцій|продукт:грами;…`. Значення КБЖВ на 100 г і ціни орієнтовні, зведені зі стандартних довідкових таблиць хімічного складу харчових продуктів; перед використанням у науковій частині їх варто звірити з офіційними джерелами (USDA FoodData Central, таблиці Скурихіна). При старті бота продукти, яких ще немає в базі, додаються автоматично, тому оновлення не потребує перестворення БД. Тест `DishCatalog_ResolvesEveryProduct` гарантує, що кожен інгредієнт кожного блюда існує в каталозі.

## Примітки щодо даних

Поживна цінність і ціни в `foods.csv` — орієнтовні довідкові значення для навчання, не офіційні дані.
Експерименти 0–3 виконуються на синтетичних даних (блюда та «холодильники» генеруються детерміновано),
тому висновки стосуються моделі, а не реальної поведінки користувачів.
